1. Claude Code 2.1.318: background subagents en MCP-blokkades

Background subagents zetten shell-commando's na 3 minuten naar de achtergrond, op alle providers. Dat voorkomt dat de prompt cache verloopt terwijl een agent op een lang commando wacht. Ook nieuw: de setting deniedMcpServers blokkeert met een URL-entry nu ook de bijpassende door Anthropic geleverde servers en connectors.

Daarnaast kan een cloud session starten met de optie "No repository", op een door Anthropic gehoste omgeving. En claude auth status toont loginExpiresAt, terwijl claude -p in JSON-output credential_expires_at meegeeft.

Probeer: draai je Claude Code headless in CI, lees dan credential_expires_at uit de JSON en laat de job vooraf falen als de login bijna verloopt. Gebruik je deniedMcpServers in een gedeelde config, check dan of de URL-regels niet ook connectors blokkeren die je wel wilt.

2. Claude Code 2.1.317: SendMessage naar background agents en hooks die blokkeren

Een SendMessage naar een draaiende background agent zet het lopende commando nu naar de achtergrond. Het bericht komt dan sneller aan, zonder dat het commando stopt. Subagents en teammates op een ander model dan het hoofdgesprek gebruiken het opgeslagen effort level van dat model, niet dat van de sessie.

Voor hooks in de Agent SDK kun je onFailure: "block" instellen. Faalt de hook-callback, dan wordt de actie geblokkeerd in plaats van doorgelaten. Claude Code vraagt ook toestemming voordat een web- of shell-aanroep je account-e-mail naar het netwerk stuurt.

Probeer: gebruik je hooks als vangnet, bijvoorbeeld om gevaarlijke commando's te scannen, zet dan onFailure: "block" aan. Een crashende hook laat dan niets meer ongezien door.

3. IP-allowlist voor Anthropic-organisaties (beta)

Sinds 5 november kun je in de Claude Console een IP-allowlist instellen. Verzoeken van adressen buiten de lijst worden geweigerd. Je kunt IPv4 en IPv6 gebruiken, ook als CIDR-range, tot 1.000 per organisatie. Het doel is dat een gelekte API-key buiten je eigen netwerk niet bruikbaar is.

Probeer: heb je backends met vaste uitgaande IP's, zoals een Docker-host of NAT-gateway, dan is dit een goedkope extra laag. Test het eerst met een niet-kritieke workspace. Zet je CI-runners erop als die ook de API aanroepen, anders val je zelf buiten de lijst.

4. Claude Code 2.1.319: details die je makkelijk mist

Gisteren stond de headline erin, hier de kleinere wijzigingen. /loop stopt nu als een self-paced beurt eindigt zonder opnieuw in te plannen. Wil je het oude gedrag, zet dan CLAUDE_CODE_LOOP_KEEPALIVE=1. Heb je een loop die zichzelf moet blijven wakker maken, dan breekt dit hem stilletjes.

Nieuw is ook /claude-api latency-optimize, en /tasks toont een rij "Earlier in this session".

Probeer: check je bestaande /loop-prompts. Plant de prompt zichzelf niet elke ronde opnieuw in, zet dan de keepalive-variabele of pas de prompt aan.
